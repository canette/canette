## Kubernetes

- Kubernetes **1.27+**
- [Gateway API CRDs](https://gateway-api.sigs.k8s.io/guides/#installing-gateway-api) installed
- A Gateway API implementation (Traefik, Cilium, Kong, nginx, etc.)
- A Gateway with an **HTTPS listener** and a TLS certificate covering `ui.hostname` and `*.{domain}` — canette does not work over plain HTTP (sign-in, sessions, OAuth and image pulls all depend on it; see [Installation](/docs/getting-started/installation#1-gateway-api-with-tls-termination))

### Example: HTTPS listener on k3s (Traefik)

k3s ships Traefik, which can act as the Gateway. Store your certificate as a TLS Secret in `kube-system` (the Gateway's namespace) — e.g. from [mkcert](/docs/self-hosting/registry) or cert-manager — then add an HTTPS listener next to the default HTTP one:

```yaml
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: traefik
  namespace: kube-system
spec:
  valuesContent: |-
    providers:
      kubernetesGateway:
        enabled: true
    gateway:
      enabled: true
      listeners:
        web:
          namespacePolicy:
            from: All
        websecure:
          port: 8443 # Traefik's internal websecure port, exposed as 443
          protocol: HTTPS
          namespacePolicy:
            from: All
          certificateRefs:
            - name: my-domain-tls # TLS Secret for ui.hostname and *.{domain}
              kind: Secret
```

This creates a Gateway named `traefik-gateway` in `kube-system`, so set `controller.gateway.name: traefik-gateway` in your canette values. The available listener keys depend on the Traefik chart version bundled with your k3s release. Verify with `kubectl -n kube-system get gateway traefik-gateway -o yaml` — the `websecure` listener should report `Programmed: True`.

## Node requirements for builds

canette builds images using BuildKit. By default it runs in **rootless mode**, which requires user namespace support on each build node. If your nodes cannot meet these requirements, see [rooted mode](#rooted-mode-fallback) below.

### Rootless mode (default)

| Distribution | Requirement |
|---|---|
| Ubuntu 24.04+ | `kernel.apparmor_restrict_unprivileged_userns=0` |
| RHEL / CentOS | `user.max_user_namespaces=28633` |
| All | Kernel ≥ 4.18 (5.11+ recommended for native overlayfs) |

### Rooted mode fallback

Some node configurations cannot support rootless BuildKit:

- **EKS Bottlerocket** — uses SELinux enforcing mode; the SELinux policy blocks the mount namespace operations that rootlesskit requires, even when user namespaces are available at the kernel level.
- Clusters running with the `Restricted` Pod Security Standard in the build namespace.
- Nodes with kernel < 4.18 or `user.max_user_namespaces=0` that cannot be reconfigured.

In these cases, set `buildkit.rootless: false` in your Helm values. This runs buildkitd as root with `privileged: true`, which bypasses the user namespace requirement entirely:

```yaml
buildkit:
  rootless: false
```

No node-level configuration is needed in rooted mode. The `privileged: true` container gets the `spc_t` SELinux label on SELinux nodes, which bypasses policy restrictions.

<Callout type="warn">
  Rooted mode is less secure than rootless — the buildkitd pod runs with full host privileges. Ensure the `{system}-build` namespace has appropriate RBAC and network policies, and that the buildkitd pod is not reachable from outside the cluster.
</Callout>

## Container registry

canette pushes built images to a registry you provide. Options:

- **In-cluster** — a plain `registry:2` deployment (no auth, for testing)
- **External** — any OCI-compatible registry (GHCR, ECR, GCR, Docker Hub, etc.)

## Resource recommendations

| Component | CPU request | Memory request |
|---|---|---|
| `canette-api` | 100m | 128Mi |
| `canette-ui` | 50m | 64Mi |
| `canette-builder` | 100m | 128Mi |
| `canette-controller` | 100m | 128Mi |
| `canette-logstreamer` | 50m | 64Mi |
| `buildkitd` | 500m | 512Mi |
| `registry` | 50m | 64Mi |
| Per build job | 250m | 256Mi |
