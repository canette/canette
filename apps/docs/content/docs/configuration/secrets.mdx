App secrets are environment variables whose values are encrypted at rest and injected into your app at deploy time.

<Callout type="info">
  This page is a work in progress.
</Callout>

## How secrets work

1. You set a secret value via the UI or API
2. canette encrypts it with AES-256-GCM using a master key stored in a Kubernetes Secret
3. At deploy time, the API decrypts the value and creates a Kubernetes `Secret` in the app's namespace
4. The secret is mounted as an environment variable in the app's `Deployment`

## Security properties

- Secret values are **never returned by the API** after being stored
- Secret values are **never logged** at any log level
- Secret values are **never stored in plaintext**
- Deleting an app deletes all its secrets (cascade)

## Setting secrets

On the app page, open **Settings → Environment**, enter the name and value, toggle **Secret** and click **Add**. The API encrypts the value before storing it.

A name can be either a plain environment variable or a secret, not both. To turn an existing variable into a secret, delete the variable first.

### Requested by an AI agent

An agent connected through [MCP](/docs/ai-agents/mcp#secrets) can't set secret values, but it can send you a link to a page that asks for specific secrets. You enter the values there yourself, so they never pass through the agent. On that page, a name that is already a plain variable can be converted to a secret in one step.

To reference a secret in your app, list its name in `canette.yaml`:

```yaml
secrets:
  - DATABASE_URL
  - STRIPE_SECRET_KEY
```
